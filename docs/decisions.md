- Detection: CoreLocation only; no raw Bluetooth scanning.
Public API: standard consumers receive `SelectBeaconSDK.configure(appKey:)`, `shared.start`, `shared.stop`, and non-sensitive `operationalStatus` updates. `SelectBeaconAppSupport` is a separate Select-owned product that exposes active beacon and pending report views through a core SPI bridge; the bridge is an organizational boundary, not security enforcement.
Enablement: the host supplies an app key before detection can start. Configuration stores the key only and never starts ranging.
API environment: production is the default (`REPLACE_ME_PRODUCTION` until the backend URL is confirmed); staging requires a caller-supplied URL so multiple staging deployments are possible. Environment cannot change after `start()`.
UUID: ship the single Select fleet UUID `76F87C5C-AB0C-45C5-8E9A-19DEF7DC2911`; internal storage remains collection-shaped for a future fleet expansion.
Identity: Major = program (Pernod = 1), Minor = unit, maps to serial.
Permission: observe the host app's authorization; never request it. Always ranges in background; When In Use ranges only while active.
Concurrency: `SelectBeaconSDK` and Apple-system adapters are main-actor isolated.
Structure: Swift Package (the SDK) plus the BeaconTest harness source for on-device testing.
Reporting: replace RSSI-improvement dedup with 60-second observation windows that aggregate `bestRSSI`, latest non-nil location, `latestTimestamp`, and `observationCount`. Close on window expiry or 30s absence; enqueue immediately on close. `stop()` finalizes open windows.
Location: low-power cached hybrid provider (coarse updates while ranging; significant-change baseline under Always). Stamp from cache only; never one-shot GPS per sighting; unavailable auth clears cache to `nil`.
Upload: batch transmit on earliest of foreground sighting-quiet debounce (60s), max queue age (300s), app background/foreground, or connectivity return; one AuthProvider token per batch; offline retain (no attempt, no backoff); failed-send exponential backoff 15s → double → cap 300s, reset on success; background ranging wakes enqueue only. Ingest is JSON:API v1 (`type` `sdk_beacon`, kebab-case attributes including `device-id`) via `POST {base}/ingest/sdk/v1` with `Authorization: Bearer`; HTTP 200 clears the whole batch. Auth is `POST {base}/ingest/auth/v1` (`app-key` / `access-token` / `expires-in`). Production host remains `REPLACE_ME_PRODUCTION` until replaced.
Auth: SDK obtains short-lived upload tokens from Select's token broker using `appKey` only. No `appSecret` and no Auth0 client secret are held or transmitted by the SDK.
Host visibility: standard consumers receive operational state only. The Select adapter exposes active beacon presence, open observation-window aggregates, durable FIFO pending-report snapshots, and stop-finalize pending; an active observation does not imply a finalized report, and empty open windows after `stop()` do not imply durable enqueue finished.
Queue concurrency: file-backed storage is actor-isolated and its interface is asynchronous so disk I/O does not run on the SDK main actor.
Delivery sessions: a serial delivery chain preserves beacon order. Only `stop()` advances `deliverySession`; `start()` must not, or stop-finalize enqueues would be dropped by an immediate restart. `stop()` invalidates pending adapter updates from prior sessions while still finalizing open windows into a new delivery; an in-flight durable write from a cancelled session cannot notify the Select app adapter. Hosts gate Start on `SelectBeaconAppSupport.isStopFinalizePending`, not on empty open windows. An empty later `stop()` leaves finalize-pending armed until the cancelled finalize task settles. Hosts may empty the durable queue with `clearPendingReports()` only after detection is stopped and stop-finalize has settled; clear intentionally overwrites corrupted queue payloads.
Corrupt queue data: never overwrite unreadable pending detections. Surface a typed queue-load error until the stored data is repaired or removed.
Serial resolution: backend, not SDK. The SDK reports UUID/Major/Minor only.
